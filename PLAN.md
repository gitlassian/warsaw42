## Идея

Карта, на которой видно, как ночью и в выходные гаснут доступные дефибрилляторы. Большинство AED стоят внутри зданий и заперты после закрытия. Поверх карты делаем инструмент для Stołeczne Centrum Bezpieczeństwa (SCB) и Budżet Obywatelski (BO), который отвечает на три вопроса:

- какие существующие AED выгоднее всего вынести в круглосуточный уличный шкаф;
- где ставить новые;
- какие записи в данных стоит перепроверить.

Как считали: 127 тыс. адресных точек (WFS города), расстояние по прямой до ближайшего публичного AED. «Ночью» означает только AED со значением `Tak`.

Поэтому часть этих записей корректна. Проверять стоит школы, библиотеки и дома культуры. Но и там, где AED выдаёт охранник, нужно позвонить и подождать, а это минуты.

**Вывод.** Проблему «AED заперты ночью» в Варшаве знают по газетам, но там только количество устройств. Анализа покрытия по времени для Варшавы, рейтинга AED для переноса наружу и аудита данных для SCB мы не нашли.

Формулировка для питча: «Media policzyły urządzenia, my policzyliśmy ludzi», то есть журналисты посчитали устройства, а мы посчитали, сколько людей остаётся без защиты и что с этим сделать.

Смерть фотографа на Plac Zamkowy можно упомянуть максимум одной фразой, уважительно и без деталей. Или не упоминать вовсе: решите командой.

## Объём на 8 часов

**Делаем:**
- карту AED с ползунком «день недели × час», на которой недоступные AED гаснут;
- счётчик покрытия и график на неделю (168 часов), радиус 100 / 200 / 400 м;
- рейтинг «вынести наружу»: топ-15 AED с наибольшим приростом ночного покрытия;
- аудит данных для SCB: подозрительные «круглосуточные», пустые часы, дубли координат;
- слой с 31 проектом BO про AED;
- README: данные, допущения, раздел про использование AI.

**Не делаем (или только слайдом):**
- пешеходные изохроны по OSM: только если на контрольной точке 2 останется время;
- оптимизатор новых мест с нуля: слайд «следующий шаг»;
- AED-квест для проверки данных: мокап одного экрана или слайд;
- живое API в демо: показываем снимок данных, сделанный в 11:00;
- мобильное приложение, аккаунты, бэкенд.

## Контракт данных между A, B и C

Фронтенд работает на моках с первой минуты, данные потом подменяются без переделок.

```jsonc
// data/out/aed.json — B
[{ "id": "622", "lon": 21.0149, "lat": 52.2086,
   "name": "Urząd Dzielnicy Mokotów", "indoor": true, "public": true,
   "status": "scheduled",            // "24/7" | "scheduled" | "unknown"
   "schedule": { "mon": [["08:00","18:00"]], "tue": [["08:00","16:00"]], "...": [], "sun": [] },
   "raw_hours": "Poniedziałek: godz. 8:00-18:00; Wtorek-Piątek: godz. 8:00-16:00",
   "suspicious": false }]

// data/out/coverage_by_hour.json — A (168 строк на каждый радиус)
{ "population": "address_points", "radii_m": [100, 200, 400],
  "hours": [{ "dow": 0, "h": 3, "available": 76, "cov": { "100": 0.3, "200": 1.7, "400": 7.1 } }] }

// data/out/relocation.json — A
[{ "id": "...", "rank": 1, "gain_pp": 0.8, "cum_night_cov": 7.9 }]

// data/out/audit.json — B
[{ "id": "...", "issue": "24/7, ale wewnątrz szkoły", "detail": "..." }]

// data/out/bo_aed.json — B
[{ "title": "Zewnętrzny AED dla Podgrodzia...", "edition": "na rok 2024", "cost": 12000, "lat": 0, "lon": 0 }]
```

Доступность AED в момент t фронтенд считает сам по `schedule`, проценты покрытия берёт из готового файла. AED со статусом `unknown` показываются серыми и в покрытие не входят. Это допущение нужно записать в README.

## Особенности данных

- Ключ API передаётся в заголовке `Authorization`, запросы только `POST https://dane.um.warszawa.pl/api/action/<action>`.
- Неверный токен или параметры дают **500 «Service unavailable»**, а не 401.
- Координаты AED вложенные: `[[lon, lat]]`.
- Budżet Obywatelski требует **и** `rok`, **и** `status` (`zrealizowane` / `w_realizacji`). Голоса в данных всегда 0. В записях есть имена авторов: не показывать (RODO).
- Реестр цен на недвижимость (RCN) отвечал 500 даже на пример из документации, не опираемся на него.
- Адресные точки без ключа: `https://wms2.um.warszawa.pl/geoserver/wfs/wfs?service=WFS&version=2.0.0&request=GetFeature&typeNames=wfs:punkty_adresowe&outputFormat=csv&srsName=EPSG:4326`

## Вопросы, которые жюри почти наверняка задаст

- **Чем это лучше Staying Alive, Mapa AED или карты 19115?** Они помогают найти ближайший AED. Мы показываем городу, где и когда AED нет, и что с этим делать.
- **Об этом уже писали в i.pl.** Да, там посчитали устройства (95 из 604). Мы посчитали, что это значит для жителей, и дали список конкретных действий.
- **Почему адресные точки, а не жители?** Это приближение. Следующий шаг: вес по этажности зданий или сетка населения GUS. Вывод от этого не меняется.
- **Почему 400 м?** 100 м как в исследованиях Копенгагена и Торонто, 400 м как щедрая оценка. Ночной провал виден при любом радиусе: 4,2% → 0,3% при 100 м.
- **В урзендах есть круглосуточная охрана.** Верно, такие записи мы считаем доступными. Сомнения вызывают школы и библиотеки. И даже с охраной нужно позвонить и ждать, а уличный шкаф открывается сразу.
- **Насколько точны часы?** Разобрали N из 710. Пустое поле у 96, но 94 из них круглосуточные (`Tak`), там часы и не нужны. Это отдельная находка для SCB: 447 уникальных формулировок на 710 записей.
- **Где вы использовали AI?** Разбор текстовых часов через LLM и помощь в коде. Всё описано в README (§4.4).
